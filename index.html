The providers, honestly

Two very different animals. gpu1.ai links to both through affiliate programs — disclosed in plain sight, because a comparison site you can't trust is worth nothing.

Vast.ai

A marketplace of independent GPU hosts bidding for your job.

  • Cheapest headline prices anywhere — hosts compete, so a 4090 dips to about $0.38/GPU/hr and an H100 to $1.34.
  • Quality varies by host. Filter by the reliability score; the cheapest offer isn't always the one that finishes your training run.
  • Best for: batch jobs, fine-tuning, experiments — anything checkpointed that can survive a host hiccup.

How gpu1.ai earns: Vast.ai pays 3% of everything you spend, for the life of your account. Your price doesn't change — the cut comes out of their side.

How the prices refresh

Nothing here is hand-typed, and your browser never talks to the providers. Prices live in a single data file, and a small scheduled job is what keeps that file fresh — this is the pipeline.

Provider APIsVast.ai live offers + RunPod pricing — both public, no keys
→
GitHub Action, hourlyfetch_prices.py pulls both APIs, normalizes to $/GPU/hr
→
prices.jsonThe bot commits the fresh snapshot back to the repo
→
Cloudflare PagesAuto-deploys the commit; the page loads the new prices.json

The cycle: every hour, at 17 minutes past, a GitHub Actions cron runs scripts/fetch_prices.py in the repo. It queries Vast.ai's public offers endpoint and RunPod's public pricing endpoint, divides multi-GPU rig prices down to a per-GPU hourly rate, and writes the result to prices.json. The Action commits that file to main, and Cloudflare Pages redeploys on every push — so new prices go live within about a minute of the fetch, with no manual step and no server to babysit.

Where it stands: both files are live in the repo — scripts/fetch_prices.py and the workflow .github/workflows/refresh-prices.yml — so the hourly cycle is running. If a fetch ever fails or the file can't be loaded, the page falls back to the snapshot baked into the page itself, and the pill in the top bar always tells you exactly which set of prices you're looking at: “Live” with the fetch time, or “Snapshot” with the baked-in one.

What you see: with the bot on, loading gpu1.ai fetches prices.json and renders the tables from it. If the file can't be loaded, the page falls back to its baked-in snapshot, so it never renders empty.

Sooner than the hour? Once the workflow is in the repo it can also be triggered by hand from the Actions tab — or run the fetch script locally and push; the next deploy picks it up either way.
